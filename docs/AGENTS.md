# docs/ — durable project knowledge

Keep architecture decisions, model inventories, benchmark evidence, runtime
compatibility results, and acceptance procedures here.

Every report must separate:

- **measured here** — reproducible local result with an environment receipt;
- **external observation** — value or behavior reported by another project;
- **interpretation** — an engineering conclusion drawn from the evidence;
- **open gate** — a question that still needs an experiment or legal review.

Do not turn an external screenshot or README number into a project guarantee.
Do not imply that two checkpoints are interchangeable because they share the
PocketTTS name. Record model revision, tokenizer, config, voice assets,
precision, and runtime whenever a result is added.

README changes should remain navigational. Detailed history belongs in a focused
report. Do not add a translated README without an explicit synchronization
policy.
